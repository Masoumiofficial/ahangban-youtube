# راه‌اندازی اتصال اختصاصی یوتیوب

این برنامه داشبورد اختصاصی شماست؛ **کانکتور رسمی Arena نیست** و نصب آن، حساب
یوتیوب را به خود عامل Arena متصل نمی‌کند. ورود و آمار خصوصی فقط در نشست مرورگر
خودتان در دسترس‌اند. برای تحلیل در گفتگو، دکمهٔ «دریافت گزارش» را بزنید و در صورت
تمایل فایل JSON را بارگذاری کنید. فایل گزارش آمار خصوصی دارد، اما توکن یا رمز ندارد.

## ۱. محیط اجرای مناسب

نیازمندی: Node.js نسخهٔ ۲۲ یا بالاتر و دسترسی اینترنت به Google.

**محیط فعلی Arena دسترسی خروجی به سرورهای گوگل ندارد.** پیش‌نمایش برای دیدن رابط
و راهنمای تنظیم است؛ تبادل توکن و دریافت آمار واقعی در این محیط قابل انجام نیست.
برنامه را روی دستگاه خودتان یا یک میزبانی دارای دسترسی به سرویس‌های زیر اجرا کنید:

- `accounts.google.com` (ورود در مرورگر)
- `oauth2.googleapis.com` (تبادل، تمدید و لغو توکن روی سرور)
- `www.googleapis.com` (اطلاعات کانال و ویدیوها)
- `youtubeanalytics.googleapis.com` (آمار خصوصی)

برای استفادهٔ شخصی روی دستگاه خودتان، `http://localhost:3000` کافی است.
برای میزبانی آنلاین یک دامنهٔ HTTPS ثابت انتخاب کنید. آدرس موقت پیش‌نمایش ممکن است
با سیاست‌های دامنهٔ Google OAuth سازگار نباشد و برای استقرار دائمی مناسب نیست.

## ۲. ساخت پروژه و فعال‌سازی API

در [Google Cloud Console](https://console.cloud.google.com/) یک پروژه بسازید.
در بخش APIs & Services → Library این دو API را فعال کنید:

1. **YouTube Data API v3**
2. **YouTube Analytics API**

API Key به‌تنهایی کافی نیست. برای آمار خصوصی، OAuth و رضایت کاربر لازم است.

## ۳. Google Auth Platform / OAuth consent screen

نام برنامه، ایمیل پشتیبانی و اطلاعات لازم را وارد کنید. برای استفادهٔ شخصی با حساب
عادی، Audience را External، وضعیت را Testing انتخاب کنید و ایمیل حساب مدیر کانال
را به Test users اضافه کنید. نام منوها ممکن است در رابط گوگل تغییر کند.

در بخش Data Access فقط دو scope زیر را اضافه کنید:

```text
https://www.googleapis.com/auth/youtube.readonly
https://www.googleapis.com/auth/yt-analytics.readonly
```

برنامه scope انتشار، ویرایش، حذف ویدیو، مدیریت کامنت یا دسترسی درآمد درخواست نمی‌کند.
در صفحهٔ رضایت باید هر دو دسترسی خواندن را تأیید کنید. در صورت تأیید ناقص، ورود رد می‌شود.
در حالت Testing، با این scopeها، refresh token معمولاً پس از ۷ روز منقضی می‌شود؛
اتصال دوباره لازم است. انتشار عمومی برای کاربران دیگر ممکن است به بررسی گوگل،
دامنهٔ تأییدشده، صفحهٔ حریم خصوصی و الزامات اضافی نیاز داشته باشد. این نمونه برای
استفادهٔ شخصی/آزمایشی طراحی شده و ادعای تأییدشدن توسط گوگل ندارد.

## ۴. ساخت OAuth Client

در Clients / Credentials یک **OAuth Client ID از نوع Web application** بسازید.
در Authorized redirect URIs آدرس دقیق زیر را وارد کنید:

```text
http://localhost:3000/auth/google/callback
```

برای میزبانی آنلاین:

```text
https://YOUR-OWN-DOMAIN/auth/google/callback
```

scheme، دامنه، پورت و مسیر باید دقیقاً با `APP_BASE_URL` و مسیر callback مطابقت کنند.
این برنامه جریان ورود سمت سرور دارد؛ JavaScript origin برای تبادل توکن استفاده نمی‌شود.
اگر `redirect_uri_mismatch` دیدید آدرس ثبت‌شده را بررسی کنید.

## ۵. تنظیم برنامه و اجرا

در محیط اجرای خودتان:

```bash
npm ci
cp .env.example .env
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

خروجی دستور آخر را برای `SESSION_SECRET` استفاده کنید. فایل `.env` را در ویرایشگر
محلی خودتان تنظیم کنید:

- `APP_BASE_URL`: آدرس پایه، مثلاً `http://localhost:3000`؛ بدون مسیر.
- `GOOGLE_CLIENT_ID`: شناسهٔ OAuth Client.
- `GOOGLE_CLIENT_SECRET`: رمز OAuth Client؛ فقط روی سرور.
- `SESSION_SECRET`: رشتهٔ تصادفی حداقل ۳۲ کاراکتری.
- `HOST`: در سیستم شخصی `127.0.0.1`؛ در میزبانی/کانتینر `0.0.0.0`.
- `PORT`: پورت داخلی برنامه، پیش‌فرض ۳۰۰۰.

**هیچ رمز، Client Secret، کد ورود یا توکنی را در گفتگو یا Git قرار ندهید.**
فایل‌های `.env` توسط Git نادیده گرفته می‌شوند. روی میزبان آنلاین از secret manager
یا تنظیمات متغیرهای محیطی همان میزبان استفاده کنید؛ secret را در فایل عمومی نگذارید.

```bash
npm start
```

اگر HOST تعیین نشود، برنامه روی `0.0.0.0` گوش می‌کند؛ فایل نمونه برای اجرای شخصی
آن را به `127.0.0.1` محدود می‌کند. برای میزبانی آنلاین HOST را تغییر دهید.
پشت reverse proxy از HTTPS و یک proxy مورد اعتماد
استفاده کنید. برنامه یک لایه proxy را مورد اعتماد می‌داند؛ در استقرار واقعی، دسترسی
مستقیم به پورت داخلی را ببندید. تنظیم secret/base URL نیاز به ری‌استارت دارد.
سرور آنلاین بدون `SESSION_SECRET` معتبر یا تنظیمات کامل اجازهٔ شروع OAuth نمی‌دهد.

## ۶. اتصال کانال

صفحه را باز کنید و «اتصال با حساب گوگل» را بزنید. با حسابی وارد شوید که کانال را
مدیریت می‌کند و اگر انتخاب Brand Account نمایش داده شد، کانال درست را انتخاب کنید.
نام، handle و شناسهٔ کانال از گوگل خوانده می‌شود؛ اگر handle با `@AhangBan` تطبیق
نداشته باشد هشدار نشان داده می‌شود، نه اینکه داده‌های کانال دیگری به نام AhangBan ثبت شود.

نقش‌های واگذارشده در YouTube Studio همیشه با دسترسی مالک در API یکسان نیستند.
اگر کانال پیدا نشد یا Analytics خطای دسترسی داد، حساب مالک یا Brand Account درست
را بررسی کنید. این برنامه از حساب، رمز یا کوکی مرورگر شما برای دورزدن مجوزها استفاده نمی‌کند.

## داده‌هایی که نمایش داده می‌شوند

- اطلاعات کانال متصل‌شده و آخرین ۱۲ ویدیوی فهرست uploads.
- آمار کل بازدید هر ویدیو از YouTube Data API.
- مجموع و روند روزانهٔ بازدید، ساعت تماشا، تغییر خالص مشترک‌ها و میانگین زمان تماشا.
- بازهٔ گزارش: ۲۸ روز، با پایان سه روز قبل از امروز برای کاهش اثر تأخیر پردازش Analytics.
  تاریخ دقیق در داشبورد دیده می‌شود؛ آماده‌بودن همهٔ داده‌ها تضمین نمی‌شود.
- نبود داده یا خطای Analytics با خط تیره/هشدار نمایش داده می‌شود، نه صفر یا آمار ساختگی.

این نسخه شامل منحنی retention، CTR، درآمد، مدیریت کامنت، انتشار ویدیو یا اجرای
خودکار اسکیل‌ها نیست. اسکیل‌های محلی مستقل‌اند و می‌توانند روی گزارشِ اشتراک‌گذاشته‌شده
و فایل‌های ورودی شما کار کنند.

## امنیت، حریم خصوصی و قطع دسترسی

- OAuth با state یک‌بارمصرف و PKCE؛ درخواست‌های حساس با CSRF token محافظت می‌شوند.
- access/refresh token در حافظهٔ موقت سرور ذخیره می‌شوند، نه localStorage یا Git.
- مرورگر فقط شناسهٔ نشست HttpOnly / SameSite=Lax می‌گیرد؛ روی HTTPS کوکی Secure است.
- مدت نشست حداکثر ۸ ساعت است؛ با ری‌استارت سرور، نشست و توکن از حافظه پاک می‌شوند.
- اطلاعات داشبورد cache عمومی نمی‌شوند؛ هیچ مسیر عمومی برای خواندن توکن‌ها نداریم.
- **قطع اتصال و لغو مجوز گوگل** ابتدا grant را در گوگل لغو می‌کند و سپس نشست را پاک می‌کند.
- اگر گوگل در دسترس نبود، «فقط خروج از این برنامه» صرفاً نشست محلی را حذف می‌کند.
  مجوز را بعداً از [اتصالات حساب گوگل](https://myaccount.google.com/connections) لغو کنید.
- پاک‌شدن نشست، خاموش‌شدن سرور یا گذشت ۸ ساعت به‌تنهایی به معنی لغو مجوز در گوگل نیست.
- هیچ فایل تحلیلی خودکار روی دیسک نوشته نمی‌شود. دانلود گزارش با اقدام خودتان انجام می‌شود.
- هر کسی که به سرور و حافظهٔ آن دسترسی مدیریتی دارد ممکن است به اسرار آن دسترسی داشته باشد؛
  برنامه را فقط روی میزبان مورد اعتماد اجرا کنید. عامل Arena نباید فایل `.env` یا توکن‌ها را بخواند.

این نسخه یک نمونهٔ تک‌سروری با نشست موقت و ظرفیت محدود است. برای سرویس عمومی
چندکاربره، نیاز به بررسی امنیتی، ذخیره‌سازی رمزگذاری‌شده و پایدار، session store مشترک،
سیاست حذف داده، مدیریت چند حساب و فرایند تأیید گوگل دارید.

## تست‌ها و محدودیت اعتبارسنجی

```bash
npm test
npm audit
```

تست‌ها با پاسخ‌های ساختگی/شبیه‌سازی‌شدهٔ گوگل اجرا می‌شوند و state، CSRF، scopeها،
نوسازی توکن، لغو مجوز، خطاها و دریافت داده را بررسی می‌کنند. آن‌ها تأیید اتصال زنده
یا مجوز حساب واقعی نیستند. تست واقعی به OAuth Client خودتان و میزبانی با دسترسی گوگل نیاز دارد.
