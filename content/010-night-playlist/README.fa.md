نام فایل `[320]` تضمین بیت‌ریت نیست؛ مثلاً فایل داریوش در سربرگ صوت 192kb/s و فایل اصلانی 128kb/s است. طول قابل‌استفاده از صوت decodeشده محاسبه شد، نه اندازهٔ فایل یا نام آن. تگ تاریخ ID3 سال انتشار اثر فرض نشده است.

صفحه‌های ahangban.ir در این محیط واکشی نشده‌اند؛ سه نشانی دقیقاً همان لینک‌های کاربرند و در توضیحات تحویلی آمده‌اند. فایل صوت از GitHub است، نه scraping وب‌سایت یا منبع جایگزین.

## گفتار و تصویر

- شش کلیپ گفتار افقی و دو کلیپ مستقل عمودی با همان هویت‌های قبلاً تأییدشدهٔ زن `voice-06` و مرد `voice-07` تولید شد. این بار دسترسی همان شناسه‌ها موفق بود؛ به انتخاب دوباره نیاز نبود.
- فایل‌های گفتار و هش‌هایشان حفظ شده‌اند؛ تغییر سرعت/زیر و بم، EQ یا ریورب گفتار انجام نشده است. فقط ضریب ثابت بلندی و میکس استفاده شد. ضبط انسانی، کلون و گفتار ردشدهٔ 007 استفاده نشد.
- سه محیط شبانهٔ تصویرسازی‌شده با هوش مصنوعی، دوربین متحرک دوبعدی، گذار نوری، کاورهای ارائه‌شده و طیف فرکانسی متصل به صوت واقعی.
- لوگوی اصلی بدون تغییر رنگ/نوشته/نسبت، روی زمینهٔ روشن قرار دارد. نام رسانهٔ آهنگ‌بان و ahangban.ir هم گفته و هم نمایش داده می‌شوند.
- هیچ گفتار یا زیرنویس گفتاری روی نمونه‌های موسیقی نیست. دعوت پایانی یک سؤال انتخاب/کامنت است.
- فایل `delivery/opening-concept.jpg` تصویر **تاریخیِ مرحلهٔ پیش‌تولید** است، نه فریم نهایی/تامبنیل فعلی.

## صداقت دربارهٔ انتخاب برش و زمان‌بندی

انتخاب پنجره‌ها با معیار فنی انرژی RMS و محدودیت طول فایل انجام شد؛ نسخهٔ عمودی پنجرهٔ مستقل ۱۲ثانیه‌ای در برش افقی دارد. این **تشخیص شعر، ترجیع‌بند، آغاز جمله یا تأیید شنیداری انسانی نیست**. کاربر باید حس و محل برش را بازبینی کند؛ در صورت نیاز با همان فایل اصلی اصلاح می‌شود.

کات‌های تصویری با افزایش انرژی صوت تنظیم شده‌اند، نه ادعای تشخیص قطعی ضرب/تمپو. زیرنویس‌ها گروه‌های کوتاهِ متناسب با متن و نزدیک به سکوت‌اند، نه forced alignment واژه‌به‌واژه. پنج هوک در فایل‌های قدیمی حفظ شده‌اند؛ نمرهٔ ابزار انگلیسی‌محور اعتبارسنجی فارسی نیست.

مرجع زمان واقعی `delivery/{youtube,reel}/timeline.json` است؛ جدول سناریو صرفاً پیش‌نویس اجرایی است. شروع موسیقی یوتیوب ۱۳٫۱۲ ثانیه است. کپشن، توضیحات، عنوان، زیرنویس و فصل‌های واقعی در delivery آمده‌اند.

## بررسی فنی انجام‌شده

- **۱۷ تست Python این قسمت + ۴۴ تست Node داشبورد/ناشر پاس شدند.**
- هر دو فایل نهایی کامل decode شدند؛ اندازه، fps و طول با تایم‌لاین تطبیق دارند.
- صوت decodeشدهٔ تک‌تک بخش‌ها با منبع اصلی/گفتار همبستگی بیش از ۰٫۹۷ دارد؛ متن نیت تدوین جای بررسی فایل نهایی را نگرفت.
- سقف نمونهٔ decodeشدهٔ افقی ‎−۲٫۰ و عمودی ‎−۱٫۹ dBFS است؛ کلیپ دیجیتال مشاهده نشد.
- حرکت دوربین و طیف صدا در فریم‌های decodeشده و عدم هم‌پوشانی گفتار/کپشن با موسیقی کنترل شد.
- چند فریم واقعی افقی/عمودی بازبینی تصویری شدند؛ این بررسی، تأیید شنیداری/احساسی کاربر یا مجوز حقوقی نیست.

## بازتولید

```bash
python3 -m pip install -r content/010-night-playlist/requirements.txt
python3 content/010-night-playlist/fetch_assets.py
python3 content/010-night-playlist/build_video.py --kind youtube
python3 content/010-night-playlist/build_video.py --kind reel
python3 content/010-night-playlist/validate_video.py --kind youtube
python3 content/010-night-playlist/validate_video.py --kind reel
python3 content/010-night-playlist/package_delivery.py
python3 -m unittest discover -s content/010-night-playlist -p 'test_*.py'
npm ci --no-audit --no-fund
npm test
```

دریافت فایل‌ها با gh و Git blob ثابت انجام می‌شود. `rendered/` شامل فایل‌های میانی و خارج از Git است. هش گفتارهای تولیدشده پیش از استفاده بررسی می‌شود؛ نیازی به تولید دوبارهٔ صدا نیست. پیش‌نیاز Python، git و gh است؛ FFmpeg از بستهٔ imageio-ffmpeg می‌آید. `build_preview.py` فقط طرح قدیمی را بازتولید می‌کند، نه ویدیو را.
