# تست واقعیِ حرکت آوا — مسیر رایگانِ انتخاب‌شده

کاربر چهره/چیدمان را تأیید کرده، طبیعی‌ترکردن میکروفون و حرکت لب/دهان/سر/حالت گوش‌دادن را خواسته است. سؤال `ava_motion_runtime` → **free_colab**: اجرای کاربر در Google Colab رایگان مجاز شد. عکس آوای مصنوعی و صدای زن06 وارد محیط Google می‌شوند؛ عامل به حساب یا اجرای Colab دسترسی ندارد. خرید/اشتراک/ارتقا یا اجرای پولی مجاز نیست.

**وضعیت صریح: در Arena هیچ استنتاج مدل و هیچ دانلود وزن انجام نشده؛ نصب/استنتاج نوت‌بوک در Colab هم هنوز آزموده نشده‌اند.** فقط اصلاح میکروفون، ورودی‌های واقعی، نوت‌بوک و کد اجرا آماده و ساختارشان محلی آزمایش شده است. نه فیلم متحرک نهایی داریم، نه تضمین سازگاری/T4/کیفیت فارسی. `motion-environment.json` نبود GPU و محدودیت دریافت وزن‌های رسمی را ثبت می‌کند؛ هیچ پراکسی/دورزدن محدودیت استفاده نشده است.

## اجرای کاربر

1. `AhangBan-Ava-Motion-Pilot.ipynb` را در Google Colab باز کند؛ Runtime → Change runtime type → **GPU رایگان**.
2. سلول‌ها به ترتیب: کنترل GPU قبل از دانلود، دریافت کد/ورودی خودِ پروژه، نصب وابستگی‌ها، دریافت وزن‌های عمومی رسمی و اجرای دو کلیپ، دریافت ZIP.
3. **اگر GPU اختصاص داده نشد، RAM/VRAM کم بود، نصب/وزن/دقت عددی خطا داد، متوقف شود؛ ارتقا/پرداخت نکند.** تأمین GPU رایگان یا زمان نصب/رندر تضمین نیست. خطا برای اصلاح برگردد؛ ورودی یا کد را خروجی حرکت حساب نکنید.
4. `ava-motion-pilot-results.zip` شامل دو کلیپ واقعی مدل و نسخهٔ پخشِ صدادارشان، گزارش ورودی/هش، مشخصات GPU و منشأ کد/وزن است. آن را برای بررسی و ترکیب در قاب آوا برگرداند. وزن‌های چندگیگابایتی داخل ZIP نتیجه نمی‌روند.

## مدل و دامنهٔ تست

کاندید جدید **EchoMimicV3 Flash** از مخزن رسمی و commit ثابت در `route.json` است، نه MuseTalk قدیمیِ ردشده. طبق README سازنده، Flash تا768×768 و ۸ گام و حداقل۱۲GB VRAM معرفی شده؛ این ادعای سازنده است، نه بنچمارک ما یا تضمین حافظهٔ Colab. نسخهٔ actor مدل 768 است، نه آوای بومی1080p. وابستگی‌ها در نوت‌بوک نسخه‌گذاری شده‌اند؛ ترکیب آن‌ها در Colab هنوز اجرا/تأیید نشده است.

دو تغییر محدود روی نسخهٔ کپی‌شدهٔ کد رسمی: استفاده از قابلیت موجود CPU-offload به‌جای دو بار بارگذاری کل pipeline روی CUDA و آزادسازی state_dict پس از بارگذاری. هدف کاهش اوج حافظه است، نه تضمین کارکرد. PIN و تعداد جایگزینی‌ها کنترل می‌شوند، هش قبل/بعد ثبت می‌شود. روی T4 از float16 و در GPU سازگار از bfloat16 استفاده می‌شود؛ سلامت عددی/بصری باید در نتیجه بررسی شود.

وزن‌ها از مدل عمومی رسمی `alibaba-pai/Wan2.1-Fun-V1.1-1.3B-InP` و بخش `echomimicv3-flash-pro` در `BadToBest/EchoMimicV3` دریافت می‌شوند. encoder چینی از پوشهٔ همان مجموعه و، اگر آنجا موجود نبود، منبع رسمیِ لینک‌شده در README یعنی `TencentGameMate/chinese-wav2vec2-base` در ModelScope دریافت می‌شود. فقط وزن دریافت می‌شود؛ صورت/صدا به HF/ModelScope ارسال نمی‌شود. نسخهٔ HF و هش فایل‌ها ثبت می‌شوند؛ در منبع ModelScope revision master درخواست شده و شناسهٔ commit تغییرناپذیر حل نشده است، پس این محدودیت بازتولید صریحاً در provenance ثبت می‌شود. توکن/ورود حساب HF لازم نیست؛ منابع gated/تغییرکرده یا checkpoint نامنطبق باعث توقف می‌شوند، نه fallback غیررسمی.

مجوز کد upstream Apache2 است؛ این به معنی تأیید مجوز همهٔ وزن‌ها، داده‌های آموزش، وابستگی‌ها، موسیقی یا انتشار تجاری نیست. هیچ انتشار/تضمین ContentID مجاز/انجام نشده است.

## ورودی ثابت و تفکیک گوش‌دادن

`prepare_pilot.py` فایل `downloads/ahangban-ava-motion-pilot-inputs.zip` را می‌سازد؛ هش در `bundle.json`. عکس actor عین فایلِ تأییدشدهٔ آواست، بدون تولید مجدد صورت یا میکروفون. مدل تنها actor روی سبز را می‌بیند؛ کاورها، عکس‌های دیوار، میکروفون و لوگو باید در ترکیب مستقل ثابت بمانند.

- **talk**: عین هوک زن06 بررسی‌شده، «شده آخر شب، یه آهنگ رو هی از اول بذاری؟»، کامل۴٫۴۸ثانیه +۰٫۳۶ثانیه سکوت انتهایی. شرط مدل mono16k و پخش stereo48k؛ هیچ کلمه حذف، سرعت/گام عوض یا صدای تازه‌ای ساخته نشده است.۱۲۱فریم در25fps =4.84s، سازگار با نسبت زمانی4n+1 مدل.
- **listen**: شرط مدل **سکوت کامل**؛ متن راهنما لب بسته، یک پلک و تکان بسیار کوچک سر/نگاه کوتاه پایین است. موسیقی مردخوانِ آهنگ اول فقط بعد از تولید، برای پخش جایگزین صوت می‌شود؛ هرگز وارد شرط لب‌خوانی نمی‌شود.۱۰۱فریم25fps =4.04s. هدایت متنی تضمین لب‌بسته یا «درک موسیقی» نیست و باید بازبینی شود.

اسکریپت از اجرای پوشهٔ خروجیِ قبلی جلوگیری می‌کند تا skip-cache کد اصلی، فیلم کهنه را نتیجهٔ تازه جا نزند. مدل کامل برای هر تست اجرا می‌شود؛ تعداد/مدت/نرخ فریم و تغییر پیکسل صورت بررسی می‌شوند، اما **این‌ها فقط QA فنی‌اند و هویت، طبیعی‌بودن و هم‌زمانی واج فارسی را ثابت نمی‌کنند**. بررسی انسانی لب/دندان/چانه/پلک، صورت/روسری و بسته‌ماندن دهان حین موسیقی پیش از اپیزود کامل لازم است. تکرار یک کلیپ کوتاه روی کل موسیقی یا زوم روی عکس جای این مرحله را نمی‌گیرد.

## پیگیری خطای جدید Colab — علت اصلی هنوز معلوم نیست

کاربر اکنون traceback حاوی `CalledProcessError` با exit code 1 برای `run_colab_pilot.py --confirm-free-or-local` فرستاده است. این خطای wrapper است؛ stdout/stderr یا exception واقعی فرایند فرزند در متن ارسالی نیست. مسیر stdlib شامل Python3.13 است. [README رسمی در commit ثابت](https://github.com/antgroup/echomimic_v3/blob/7e89489ca51c0d008fc1963ec6c03fc5bd0b9397/README.md) نسخه‌های تست‌شده را **3.10 و 3.11** ذکر می‌کند؛ این نشانهٔ ریسک سازگاری است، **نه اثبات علت خطا یا ناممکن‌بودن اجرا روی3.13**. وابستگی‌ها کورکورانه ارتقا/تنزل داده نشده‌اند.

### فقط تشخیص؛ بدون تکرار مدل

محتوای [`quick_diagnostic_cell.py`](quick_diagnostic_cell.py) را در **همان runtime خطاداده** در یک سلول تازه اجرا کنید. کل نوت‌بوک را Run all نکنید. این بررسی فقط نسخهٔ Python/بسته‌ها، وضعیت GPU، وجود خروجی و گزارش خطای ذخیره‌شده را می‌خواند؛ بدون نصب، دریافت وزن، استنتاج، حذف فایل یا ارسال به سرویس دیگر. نام/VRAM دستگاه فقط در صورت قابل‌استفاده‌بودن CUDA بررسی می‌شود؛ هیچ tensor/model روی GPU ساخته نمی‌شود. کد Torch در فرایند جدا با timeout۳۰ثانیه است. خروجی آن برای بررسی محیط است و لزوماً علت خطای تاریخی را مشخص نمی‌کند.

نسخهٔ کامل‌تر `diagnose_runtime.py` علاوه‌بر این‌ها، هش ZIP ورودی را هم کنترل می‌کند. اگر کد جدید **از قبل** در runtime موجود است:

```python
import subprocess, sys
subprocess.run([sys.executable, '/content/ahangban-youtube/content/011-ava-split-screen/motion/diagnose_runtime.py'], check=True)
```

### اصلاح گزارش‌دهی، نه ادعای رفع مدل

- اجرای صریحِ سلول استنتاج در نسخهٔ جدید، stdout/stderr واقعی را هم‌زمان چاپ و در `logs/colab-run-<id>.log` ذخیره می‌کند؛ آخر خطا نیز tail فرایند فرزند را نشان می‌دهد، نه فقط exit1. هیچ retry خودکار ندارد.
- فرمان‌های داخلی هم لاگ جدا دارند؛ `failure-summary.json` مرحله و exception آخر را ثبت می‌کند. لاگ‌ها نام یکتا و ایجاد انحصاری دارند؛ لاگ قبلی بازنویسی نمی‌شود. خلاصه مربوط به آخرین شکست است.
- از اجرای قدیمی که لاگ ذخیره نکرده، خطای داخلی را نمی‌توان به‌صورت پس‌نگر از `CalledProcessError` بازیابی کرد. برای همین فعلاً فقط تشخیص محیط، نه اجرای مجدد مدل، توصیه می‌شود.
- سلول دریافت کد، **همان شاخه** را فقط fast-forward به‌روز می‌کند؛ در تعارض/تغییر محلی توقف دارد، نه reset یا پاک‌کردن وزن/ویدئو. پوشهٔ خروجی قبلی هم همچنان مانع تکرار کورکورانهٔ مدل می‌شود؛ **آن را برای عیب‌یابی حذف نکنید**.
- ۱۳ آزمون stdlib/CPU برای ثبت خطای واقعی، نگه‌داری لاگ، تشخیص خواندنی، timeout و محافظ خروجی اجرا شدند. این‌ها تست Colab/CUDA/نصب/استنتاج یا تأیید حرکت و لب‌خوانی نیستند. دو MP4 قبلیِ آوای ثابت دست‌نخورده‌اند.

## خطای داخلی اکنون دریافت شد: `Missing official model component: .../base/transformer`

بخش قبلی مربوط به زمانی بود که فقط wrapper در دست بود؛ اکنون مرحلهٔ شکست **دریافت/کنترل مدل پایه، قبل از استنتاج** مشخص است. کاربر GPU فعال Tesla T4 با14.56GiB، Python3.13.16، Torch2.11.0+cu130 و بارگذاری موفق کتابخانه‌های اصلی را گزارش کرده است. این خطای مشخص نشانهٔ OOM یا اشکال Python نیست؛ مشکلات احتمالی مراحل بعد هنوز آزموده نشده‌اند.

**اشکال در کد آماده‌سازی ما بود:** فیلتر دانلود فقط پوشه‌های `transformer/*`، `vae/*`، `text_encoder/*` و… را می‌گرفت؛ سپس همان پوشه‌ها را الزامی می‌دانست. درحالی‌که [`config/config.yaml` رسمیِ ثابت](https://github.com/antgroup/echomimic_v3/blob/7e89489ca51c0d008fc1963ec6c03fc5bd0b9397/config/config.yaml) چنین مسیری دارد:

- transformer: `./`؛ `config.json` و وزن تکی/شاردهای ریشه، نه `transformer/`.
- VAE: فایل `Wan2.1_VAE.pth`، نه پوشهٔ `vae/`.
- متن: فایل `models_t5_umt5-xxl-enc-bf16.pth`.
- تصویر: فایل `models_clip_open-clip-xlm-roberta-large-vit-huge-14.pth`.
- tokenizer: `google/umt5-xxl/`.

هش SHA256 تنظیمات رسمی خوانده‌شده: `21fe4409b664385a1c1cc5c23d92506ffb05ef3c374a18de9df67b715dca07e9`.

`model_assets.py` اکنون ابتدا فهرست فایل‌های **همان revision حل‌شدهٔ مخزن رسمی** را بررسی می‌کند و فقط نام‌های موردنیاز را به دانلود می‌فرستد. ساختار ناشناخته/شارد ناقص پیش از دانلود سنگین متوقف می‌شود. کنترل بعدی روی فایل واقعی و config است، نه ساختن پوشهٔ خالی برای عبور از خطا. فایل/کش/ویدئوی قبلی حذف نمی‌شود. هش وزن‌های بزرگ نیز به‌صورت قطعه‌ای محاسبه می‌شود تا T5 چندگیگابایتی یکجا وارد RAM نشود.

### ترمیم فقط دریافت مدل‌ها — بدون اجرای ویدئو

در **همان runtime رایگان**، فقط این سلول را اجرا کنید؛ نه نصب دوباره و نه Run all:

```bash
%%bash
set -euo pipefail
cd /content/ahangban-youtube
test "$(git branch --show-current)" = 'arena/d4ba4e0b-ahangban-youtube'
git pull --ff-only origin arena/d4ba4e0b-ahangban-youtube
python3 -u content/011-ava-split-screen/motion/run_colab_pilot.py \
  --confirm-free-or-local --prepare-models-only 2>&1 | tee "/content/ava-model-repair-$(date +%s).log"
```

این حالت **ممکن است چندین گیگابایت فایلِ پایهٔ قبلاً دریافت‌نشده دانلود کند**، ولی GPU/model/inference را راه نمی‌اندازد و پوشهٔ خروجی ویدئو را نمی‌سازد/حذف نمی‌کند. دانلود اجباری تنظیم نشده؛ HF/ModelScope از کش معتبر قبلی استفاده می‌کنند. هیچ توکن/رمز یا خرید لازم نیست؛ اگر Git به تغییر محلی/تعارض برخورد کرد reset نکنید، همان خطا را برگردانید.

علامت پایان مرحله: **`MODEL_FILES_READY_NO_INFERENCE`**. این فقط تأیید کنترل فایل‌هاست؛ نه تأیید بارگذاری مدل، سازگاری Python3.13، کفایت RAM/VRAM یا موفقیت رندر/حرکت فارسی. اجرای واقعی بعدی همچنان محافظ خروجی قدیمی را دارد.

**آزمون‌ها:** ۱۵ تست جدید برای بازتولید فیلتر قبلی که فقط۲فایل مستندات را انتخاب می‌کرد، انتخاب مسیرهای تخت، شاردها/فایل ناقص، حفظ کش، هش قطعه‌ای و حالت دانلودِ بدون استنتاج؛ همراه۱۳تست تشخیص قبلی = **۲۸تست CPU/stdlib پاس**. هیچ وزن واقعی در Arena دانلود و هیچ اجرای Colab/GPU انجام نشده؛ اصلاح کد هنوز باید در Colab تأیید شود.
